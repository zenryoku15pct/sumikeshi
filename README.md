# スミケシ（sumikeshi）— 検証機能つきPDFマスキングツール

手書き書類を連続スキャンしたPDFの「毎ページ同じ位置」にある個人情報（氏名欄など）を、
マウスドラッグで矩形指定して**全ページ・複数PDFに一括マスキング**するデスクトップアプリです。
ネットワークは一切使いません。

学校現場（生徒の答案・調査票をAIサービス等に渡す前の下ごしらえ）を想定して作りましたが、
アンケート・申込書など「同じ様式の紙が大量にある」場面なら同じように使えます。

**ほかの黒塗りツールと違う点は、塗ったあとに「本当に消えたか」を機械で全ページ検査できることです。**

## 特長

- **復元不可能なマスキング**：黒い四角を上に重ねるだけの「見た目の黒塗り」ではなく、
  PDF内の画像データそのもの（ピクセル）を消去します。あとから剥がして中身を見ることはできません。
- **マスキングと同時に自動検査**：塗ったあと、書き出したPDFを読み直して本当に消えたかを
  機械で確かめ、消え残りがあれば画面に✕を出します。**画面の「✓ 枠内クリア」は
  「指定した枠の内側について消え残りが見つからなかった」という意味です。**
  枠の縁を横切って外へ続く字（枠より長く書かれた氏名）は⚠で知らせますが、枠から離れた
  別欄・対象外にしたページ・ファイル名は見ていません（用紙全体の安全保証ではありません）。
  検査は、目視では追えない枚数と、スキャナのMRC圧縮が作る隠れた画像レイヤーまで見ます
  （あとから単体で検査し直すこともできます＝`check_masked.py`）。
- **OCR（文字認識）テキスト層・メタデータも除去**：スキャナが埋め込んだOCRテキストのうちマスク領域内の
  文字を正規の墨消し処理で除去し、PDFのメタデータ（タイトル・作成者・XMP）も自動で消去します。
- **完全ローカル処理**：外部への送信は一切ありません。読み込んだPDFは表示のために読むだけで、
  原本ファイルは変更しません。外部との通信・ネットワークの待ち受けはありません
  （二重起動を防ぐための、PC内だけの接続口は使います）。
- **複数PDF一括・ファイルごとの個別設定・プリセット保存**に対応。

## 入手方法

### A. 実行ファイル版（推奨・Pythonのインストール不要）

[Releases](../../releases) から自分のOSのZIPをダウンロードして展開するだけです。
（Windowsは**ZIPを右クリック→「すべて展開」**してから使ってください。ZIPを開いた
ウィンドウの中で直接ダブルクリックすると、必要なファイルがそろわず動きません）

| ファイル | 対象 | ダブルクリックするもの |
|-|-|-|
| `sumikeshi-windows.zip` | Windows | `sumikeshi.exe` |
| `sumikeshi-macos-apple-silicon.zip` | Mac（Appleシリコン：M1以降） | `スミケシ.app` |

（Intel Mac＝2020年頃までの機種は、下の**ソース版**を使ってください）

ダブルクリックすると**アプリのウィンドウがそのまま開きます**。黒い画面（ターミナル）もブラウザも
出ません。終了はウィンドウを閉じるだけです。
マスキング後の検査は、アプリの中の「**検査**」から行います。

同じフォルダの `お試し用PDF/ダミー調査票.pdf` は、練習用の架空の書類です（4ページ・
氏名欄はすべて架空の名前）。まずはこれで、矩形を1つ引けば全ページから消えることを
試してみてください。

**初回だけ、OSの警告が出ます**（開発元の署名を購入していないためで、異常ではありません。
中身はこのページで公開しているソースそのものです）：

- **Windows**：青い「WindowsによってPCが保護されました」→「**詳細情報**」→「**実行**」
- **macOS**：「開発元を検証できません」→ システム設定 → プライバシーとセキュリティ →
  下部の「**このまま開く**」（古いmacOSでは右クリック→「開く」でも可）

**ウイルス対策ソフトが `sumikeshi` を誤って削除する場合があります。**
署名のないPython製アプリに起きやすい誤検知で、ウイルスではありません
（中身はこのページで公開しているソースそのものです）。その場合は、お使いのウイルス対策ソフトの

## 使い方（5ステップ）

1. **PDFを読み込む** — 画面左にPDFをドラッグ＆ドロップ（複数可）
2. **マスク位置を指定** — 右のページ表示の上をドラッグして矩形を追加（複数可）。
   ページ送り（◀▶ または ←→キー）で他のページの位置ズレを確認。
   矩形はクリックで選択、ハンドルでサイズ変更、Deleteで削除。ファイルごとに記録されます。
   **枠は欄の印刷線より一回り大きく**（ふりがな・訂正書き・はみ出した字ごと囲む）。
3. **設定** — 塗りつぶし色（黒/白）、適用ページ範囲（空欄=全ページ）、奇数/偶数ページのみ
   （両面スキャン対応）。「この設定を全ファイルへコピー」で一括設定もできます。
4. **マスキング実行** — `output/` に `元ファイル名_masked.pdf` として保存されます
   （原本は無変更）。矩形を引いていないPDFは処理されず、出力もされません。
   **`output/` の直下に置かれるのは「枠内クリアの最新版」だけ**です。
   要確認・消え残りの出力は `output/要確認/` に `_要確認` 付きの名前で分けて置かれます。
   同じ原本を塗り直すと、同じ置き場にある古い同名の出力は `trash/` へ退避されます
   （枠内クリア→要確認のように置き場が変わった場合、前の出力はそのまま残ります）。
5. **もう一度「検査」** — 渡すフォルダそのものを「検査」に掛けられます。処理し忘れの原本が
   紛れていれば、検査項目[0]（処理済みの印）で要確認になります。
   実行直後の✓は「今回処理したファイル」の話で、後から足したファイルは見ていません。
   検査するのはフォルダ直下のPDFだけで、`要確認/` などの中のフォルダは含みません。

## 全ページ自動検査

マスキング後のPDFを機械で全ページ検査します。

- **アプリから**：画面左の「**検査**」→「マスク済みPDFを検査する…」→ フォルダを選び、
  「マスク範囲」で「いま画面の矩形」か保存したプリセットを選んで実行。
  ファイルごと・ページごとの結果が一覧で出ます
- **コマンドから**（ソース版・大量処理や自動化向け）：

```
python3 check_masked.py output/
```

（Windows は `.venv\Scripts\python check_masked.py output\`）

どちらも `検査レポート/検査レポート_日時.md` にページごとの合否表が残ります
（`output/` の外に置くのは、レポートにはファイル名や元のメタデータが載るため、
人に渡すフォルダへ紛れ込ませないためです）。
コマンド版の終了コードは 合格=0 / 不合格・要確認あり=1。

### 検査項目

|項目|見るもの|不合格・要確認になる例|
|-|-|-|
|[0] 処理痕跡|残存メタデータが無いか・**処理済みの印**があるか|そもそもツールを通っていないファイルが紛れている（印の無いPDFは要確認）|
|[1] 画像レイヤー|**全レイヤー**のマスク領域が均一か|黒い四角を重ねただけ／MRCの下層に氏名が残る|
|[1.5] 枠の縁|枠のすぐ外側に、縁につながる暗い部分（字のはみ出し）が無いか（要確認どまり）|氏名が欄より長く書かれていて、最後の1字が枠の外に残る|
|[2] テキスト層|マスク領域内の文字が0か|OCR文字が黒塗りの下に残っている|
|[2.5] 線画|マスク領域に掛かる線（ベクターの筆跡）が無いか|タブレット記入の署名が黒塗りの下に座標のまま残っている|
|[3] 注釈|注釈が0件か（PDFの生の一覧から数える）|注釈で黒塗りしている（剥がせる）／フォーム入力欄に氏名が残る|
|[4] レポート|上記をページごとに表で出力|—|

出力のPDFには「スミケシで処理済み」の小さな印（個人情報を含まないメタデータ1項目）が
入ります。検査は印の無いPDFを「未処理の疑い」として要確認にします。

**[1]がこのツールの肝です。** スキャナのMRC圧縮は1ページを複数の画像レイヤーに分けて
持つため、見た目が真っ黒でも下の層に文字が残ることがあります。全レイヤーを個別に取り出して、
マスク領域のピクセルが均一かどうかで判定します。

### マスク領域の決め方（コマンド版・3段構え）

（アプリでは、画面で引いた矩形か、検査画面で選んだプリセットを使います）

1. `--preset 名前` または `--rects "x0,y0,x1,y1"` で明示指定 ← **最も確実**。
   座標は用紙の左上を (0,0)・右下を (1,1) とする割合で、左・上・右・下の順に書きます
2. 指定がなければ自動検出（黒の均一ブロックを探す）
3. どちらでも見つからなければ「マスク痕跡なし」として要確認にする（黙って合格にはしません）

自動検出は黒だけが対象です。白で塗ったPDF向けに `--detect-white` もありますが、
紙の余白と区別しにくいため、`--preset` か `--rects` で領域を渡す方が確実です。

## 検査の限界

**「✓ 枠内クリア」＝指定したマスク枠の内側について消え残りが見つからなかった、という
意味です。** 用紙全体の保証ではありません。次は機械では見ていません。

1. **枠からのはみ出し**：氏名が矩形からはみ出して書かれている・スキャンの置きずれ・
   コピーの変倍でレイアウトがずれている場合、枠の外に残った部分は消えません。
   枠の縁を横切って続く字は検査[1.5]が⚠で知らせますが、薄い字・細い画・枠から離れた位置や
   四隅の斜め外側の字は見つけられず、字の途中で枠を切った場合も切った位置によっては
   見つけられません（要確認にするための仕組みであって、合格の根拠ではありません）。
   → **対策は矩形を気持ち大きめに囲むこと**（これが本質的な防御です）。
   束の一部のページだけ枠の下が空白のときは「そのページだけ枠がずれていませんか」と
   警告が出ますが、ずれた先に別の印字があると機械には見えません。
2. **押さえ忘れた別欄**：保護者署名・緊急連絡先・自由記述の中に書かれた名前など、
   指定していない欄は検査対象外です。
3. **マスクは匿名化ではありません**：氏名欄を消しても、筆跡・記述の内容・学級名などから、
   本人や周囲の人には誰の書類か分かります。
4. **ファイル名は検査対象外です**：氏名入りのスキャン名は出力にも引き継がれ、
   検査レポートにもそのまま載ります。
5. **ページ範囲・奇数偶数で外したページは検査もされません**：対象外のページの枠の
   場所に中身が残っていれば⚠で知らせますが、✓の対象は処理したページだけです。

なお、次の危ない紙は**塗らずに止まります**：
束の中に縦横比・向きの違うページが混じっている／切り取り（トリミング）がある／
読み込んだあとに原本が差し替わった。止まったときは、表示された理由に従って
PDFを整えてから読み込み直してください。

## この道具が向かない仕事

- **ページごとに塗る場所・塗る範囲の判断が変わる文書**——会議録、指導記録、
  開示請求への対応（不開示部分の墨塗り）、自由記述の中に散らばる実名。この道具は
  「毎ページ同じ位置」を一括で塗るための物で、**「どこを塗るべきか」の判断は一切
  保証しません**。検査が見るのは「塗ると決めた場所が消えたか」だけです。

## 用紙の作りと自動検出

- 黒い帯・黒背景の見出しがある用紙では、マスクの自動検出がそれをマスク候補と
  取り違えることがあります（自動検出だけでは合格にはなりません）
- 氏名欄の周囲に余白がある用紙ほど、矩形を大きめに囲めます

## コツ・注意

- スキャンは1〜2mmずれることがあるため、**矩形は気持ち大きめ**に囲んでください
- ファイル名に個人名が入っている場合、出力ファイル名にも引き継がれます
- **プリセットは様式の変更を知りません。** 枠の位置・色・ページ指定・紙の形（縦横比と向き）を
  保存しますが、同じ形のまま欄の位置だけ変わった様式は機械には見えません
  （形の違う紙に当てたときは実行時に止まります）
- 白で塗ると、塗った場所も塗り残しも目では確認しにくくなります。**白を使うときこそ矩形を
  大きめに**（白なら大きめに囲っても見た目は変わりません。囲った範囲の文字・罫線も消えます）

## フォルダ構成

| ファイル/フォルダ | 内容 |
|---|---|
| `gui.py` | 画面（PySide6）。アプリの入口 |
| `masking.py` | マスキングの中核（画面から独立。PyMuPDFのリダクション） |
| `check_masked.py` | マスク後の全ページ自動検査（コマンドとしても単体で動く） |
| `make_dummy_sample.py` | お試し用ダミーPDF（架空の氏名入り）の生成 |
| `assets/` | アイコンなど |
| `output/` | マスキング済みPDFの出力先（直下は枠内クリアの最新版だけ） |
| `output/要確認/` | 要確認・消え残りの出力（`_要確認` 付きの名前） |
| `検査レポート/` | 検査レポート（ファイル名・元メタデータが載るため出力とは分ける） |
| `presets/` | 保存した矩形設定（JSON） |

出力先（`output/` `presets/`）は、Windowsではexeと同じフォルダ、macOSでは
`スミケシ.app` と同じ階層にできます。そこに書き込めない場合（`/アプリケーション` など）は
`書類/スミケシ/` の下に、そこにも書けなければ一時フォルダの下にできます。
画面の「出力フォルダを開く」で確認できます。
